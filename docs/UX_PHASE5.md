# Phase 5 UX実装方針

作成日: 2026-09-05

対象:

- サイトのレスポンシブ対応
- 製品ページの閲覧履歴

## 優先順位

1. サイト全体のレスポンシブUX監査・改善
2. 製品ページの閲覧履歴
3. Public GitHub Repository Import MVP

レスポンシブ改善を先にする理由は、全ページ・全訪問者へ効果があり、閲覧履歴やGitHub Importを追加する前にモバイル上の共通UI基盤を整えられるため。

## 1. レスポンシブ対応

### 現状

サイトは既に完全なデスクトップ固定レイアウトではない。

`src/styles.css` には次の基礎対応がある。

- `860px` 以下で3列カードを2列化
- 2カラム製品ページを1カラム化
- リリース変更点を1カラム化
- `620px` 以下でカードを1列化
- ヘッダーを縦積みへ変更
- 表を `.table-wrap` の横スクロールで保護
- フォーム/履歴/カレンダーの一部をモバイル向けに再配置
- フッターを1カラム化

したがって「レスポンシブ化」ではなく、**既存レスポンシブの実機幅UX監査と不足箇所の修正**として実施する。

### 改善対象

#### モバイルナビ

現状は620px以下でメインナビ全リンクを縦に積むため、sticky headerが画面上部を大きく占有する可能性がある。

改善案:

- モバイル時はメニューボタンで開閉
- JavaScript無効時でもリンクへ到達できる構造を維持
- `aria-expanded` / `aria-controls` を設定
- Escapeで閉じる
- メニュー外リンク選択時に閉じる
- desktopでは現在の横並びを維持

#### タップ領域

- ナビリンク、絞り込み、ページ送り、フォームボタンを44px前後の操作領域に統一
- リンクが密集するフッターもモバイルでは間隔を確保

#### 表

現在の横スクロール方式は維持する。

追加候補:

- モバイル時に「横にスクロールできます」を視覚的に示す
- 表をカードへ強制変換しない（EOL日付の列比較性を維持するため）
- 最重要列が画面外になりすぎる表だけ列幅を再調整

#### 製品ページ

- サイドパネルが1カラム化した際の情報順序を確認
- 「どうすればいい？」が本文末尾まで下がりすぎる場合はモバイル用要約を上部へ移動
- 長いURL/コード/SHA-256が横幅を破壊しないことを確認

#### フォーム

- マイEOL
- Slack / Discord設定
- メール通知
- Calendar
- Search / filter

について320px幅でも横スクロールを発生させない。

#### safe area

iPhone等で固定UIがホームインジケータと重ならないよう、back-to-top等に `env(safe-area-inset-*)` を考慮する。

### 確認幅

最低限、以下で確認する。

- 320px
- 360px
- 390px
- 430px
- 768px
- 1024px
- 1440px

### 完了条件

- ページ本体に意図しない横スクロールがない
- 主要操作がタップしやすい
- sticky headerがモバイル画面を過度に占有しない
- EOL表は情報を欠落させず閲覧できる
- マイEOL/通知設定が320pxでも操作可能
- `npm run check && npm run build && npm run validate:seo` が成功

## 2. 閲覧履歴

### 保存方式

既存のTracked Productsと同様、ブラウザのlocalStorageへ保存する。

候補キー:

```text
eol-jp:view-history:v1
```

サーバー、Cloudflare KV、メール通知基盤へは送信しない。

### 保存対象

製品詳細ページ `/eol/{slug}/` の閲覧のみ。

一般ページ、検索語、通知設定、GitHub URL等は履歴として保存しない。

### データ構造

```ts
type ViewedProduct = {
  slug: string;
  label: string;
  viewedAt: string;
};

type ViewHistoryState = {
  schemaVersion: 1;
  items: ViewedProduct[];
};
```

### ルール

- 同じ製品を再閲覧したら重複追加せず先頭へ移動
- `viewedAt` を最新に更新
- 最大20製品
- 不正JSONは空状態へフォールバック
- 個別削除または全履歴削除を提供
- localStorage使用不可でも製品ページ閲覧を妨げない

### 表示場所

初期実装では次の2か所を候補とする。

1. `/eol/` の上部に「最近見た製品」
2. `/my-eol/` に「最近見た製品」

メインナビに新しい「履歴」リンクは追加しない。現在でもモバイルナビ項目が多く、専用ページを増やすより既存導線内で表示した方が負荷が低い。

### プライバシー表示

「閲覧履歴はこのブラウザ内だけに保存され、サーバーには送信されません」と明記する。

### テスト

`src/lib/view-history.ts` の純粋関数を用意し、Nodeテストで以下を検証する。

- 空状態
- parse失敗
- 追加
- 同一slugの重複除去
- 再閲覧時の先頭移動
- 20件上限
- 個別削除
- 全削除

### 完了条件

- 製品閲覧で履歴が更新される
- 履歴から製品ページへ戻れる
- 削除操作ができる
- private browsing / localStorage無効でもページ自体は壊れない
- 外部送信を行わない
- ユニットテスト、Astro check、build、SEO validationが成功
